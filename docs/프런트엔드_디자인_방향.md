# CarMe 프런트엔드 디자인 방향

## 디자인 리드

모바일 우선의 차량 매뉴얼 보조 서비스로, 고령 사용자도 빠르게 읽을 수 있는 차분하고 안전 중심의 `driver guide` 언어를 사용한다. 현대자동차의 판매 페이지가 아니라 CarMe 고유의 유틸리티 디자인 시스템을 만든다.

| 설계 축 | 값 | 이유 |
|---|---:|---|
| Design variance | 3 / 10 | 안전·신뢰가 우선인 서비스이므로 예측 가능한 정보 구조를 사용한다. |
| Motion intensity | 2 / 10 | 차량 문제를 해결하려는 상황에서 장식적 움직임은 집중을 해친다. 상태 전환과 버튼 피드백만 사용한다. |
| Visual density | 5 / 10 | 상담, 근거, 경고를 한 화면에 읽기 좋게 보여 주되 과밀하게 만들지 않는다. |

## 1. 현대 참고 원칙

첨부한 현대 화면에서 참고할 것은 **차량을 중심에 두는 맥락, 넓은 여백, 선명한 정보 계층, 차가운 중립색의 안정감**이다.

복제하지 않는 요소는 다음과 같다.

- 현대 로고, 워드마크, 고유 서체, 정확한 브랜드 네이비와 헤더 비율
- 판매 페이지처럼 차량 이미지가 가장 큰 비중을 차지하는 히어로 구조
- 현대 사이트의 메뉴 아이콘, 행 구성, 문구, 메뉴 정보구조
- 현대차 공식 서비스로 오해될 수 있는 이름이나 화면 표현

CarMe는 화면 하단 또는 설정에 `CarMe는 현대자동차 공식 서비스가 아니며, 공식 매뉴얼을 참고해 안내합니다.`를 표시한다. 차량 이미지는 권한이 확인된 자산만 사용하며, 초기 화면에서는 차량 사진보다 차량명·연식으로 맥락을 만든다.

## 2. 컨셉: Quiet Driver Guide

`Quiet Driver Guide`는 운전자의 옆에서 필요한 매뉴얼 쪽을 조용히 펼쳐 주는 안내서다.

- **첫 행동:** "무엇이 불편하신가요?"라는 큰 질문 입력창
- **차량 맥락:** 상단의 작은 차량 선택 바. 차량은 배경이 아니라 질문의 검색 범위를 정하는 정보다.
- **답변의 중심:** 해결 안내보다 근거와 주의사항을 같은 위계로 보여 준다.
- **안전 상태:** 일반 답변과 위험 전환을 시각적으로 명확히 구분한다.
- **말투:** 짧고 직접적이다. "확인해 보세요", "매뉴얼 87쪽에서 확인할 수 있어요"처럼 행동과 근거를 함께 말한다.

## 3. 색상 토큰

현대의 차분한 푸른 계열 분위기는 참고하되, CarMe는 더 회색에 가까운 청색을 단일 강조색으로 사용한다. 일반 CTA, 링크, focus ring은 모두 이 강조색을 공유한다.

### Light theme

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg` | `#F4F7F8` | 전체 배경 |
| `--surface` | `#FFFFFF` | 카드, 입력창, 모달 |
| `--surface-muted` | `#E8EEF1` | 차량 선택 바, 정보 구역 |
| `--text-primary` | `#18232D` | 제목, 본문 핵심 정보 |
| `--text-secondary` | `#53616C` | 보조 설명 |
| `--border` | `#CAD4DA` | 입력창, 분리선 |
| `--accent` | `#1F5E84` | 기본 버튼, 링크, focus |
| `--accent-hover` | `#174865` | hover, pressed |
| `--safety` | `#B2412F` | 위험 전환만을 위한 의미 색상 |
| `--success` | `#277354` | 해결 완료 상태만을 위한 의미 색상 |

## 4. 타이포그래피와 형태

| 요소 | 규칙 |
|---|---|
| 본문 폰트 | `Pretendard Variable`을 self-host하고, 시스템 sans-serif를 fallback으로 둔다. |
| 제목 | 700 weight, 짧은 문장, 모바일 28-32px부터 시작한다. |
| 본문 | 최소 16px, 줄간격 1.6 이상. 근거·안전 안내는 17px까지 허용한다. |
| 버튼 | 최소 높이 48px, 16px 이상 텍스트, 한 줄 레이블만 사용한다. |
| 카드 | 16px radius, 얇은 border, 그림자는 차량 선택과 modal처럼 계층이 필요한 경우에만 쓴다. |
| 입력창 | 14px radius. label은 placeholder와 별도로 입력창 위에 둔다. |
| 아이콘 | 한 라이브러리만 사용한다. Vue 구현 시 Tabler Icons를 기본 후보로 둔다. |

## 5. 홈 화면 정보 구조

```text
상단: CarMe 텍스트 로고 + 내 차량 선택
  ↓
차량 맥락 바: "아반떼 2025" / 차량 변경
  ↓
주요 질문: "무엇이 불편하신가요?"
검색 입력창 + 전송 버튼
  ↓
빠른 시작: 시동·주행 / 경고등 / 공조·편의 / 비상시
  ↓
최근 상담 또는 "상담 기록이 아직 없어요" empty state
```

차량 이미지를 처음부터 크게 쓰지 않는다. 사용자가 차량을 바꾸거나 매뉴얼 화면에서 원할 때만 작은 썸네일 또는 적법한 이미지로 보조한다. 홈의 시선은 차량이 아니라 질문 입력창에 둔다.

## 6. 상담 결과 화면

| 상태 | 화면 규칙 |
|---|---|
| `GROUNDED` | 답변 요약, 주의사항, 근거 카드, 원문 보기 순서. 인용은 답변 아래에 접어서 두지 않는다. |
| `AMBIGUOUS` | 다음 답변에 필요한 질문 하나만 크게 제시한다. |
| `INSUFFICIENT_EVIDENCE` | 회색 정보 구역에 확인 불가 이유와 고객 지원 경로를 표시한다. |
| `SAFETY_ESCALATION` | safety 색상과 명확한 제목을 사용한다. 일반 답변 카드보다 위에 두고, 애니메이션으로 주의를 흐리지 않는다. |

근거 카드는 문서명, PDF 페이지, 짧은 원문 인용, `원문 보기` 버튼으로 구성한다. 페이지 번호는 링크 색상만으로 의미를 전달하지 않고 텍스트로도 표시한다.

## 7. 인터랙션과 접근성

- 로딩은 질문·답변 레이아웃과 같은 형태의 skeleton으로 표시한다.
- 버튼은 hover보다 focus와 pressed 상태를 우선한다.
- 자동 재생, parallax, 무한 애니메이션은 사용하지 않는다.
- dark mode는 시스템 설정을 기본으로 하며 수동 토글을 제공한다.
- 320px 화면에서 한 열로 보이고, 데스크톱에서는 최대 폭 1,120px 안에서만 확장한다.
- 오류 문구, placeholder, 보조 텍스트까지 WCAG AA 대비를 만족해야 한다.

## 8. 구현 전 디자인 체크리스트

화면별 초기 레이아웃과 정상·예외 상태는 [모바일 와이어프레임](./와이어프레임.md)을 기준으로 한다.

- [ ] `src/styles.css`를 CSS 변수 기반 light/dark 토큰으로 교체
- [ ] Pretendard self-host 방식과 라이선스 확인
- [ ] Tabler Icons 설치 후 아이콘 규칙 통일
- [ ] 기본 App을 홈 정보 구조로 교체
- [ ] 차량 선택, 세션 종료/만료, 로딩, 네 가지 상담 상태의 화면 시안 작성
- [ ] 모바일 320px와 dark mode에서 대비·터치 영역 점검
- [ ] 현대 로고·공식 워드마크·무단 차량 이미지가 화면에 없는지 점검

## 9. 관리자 화면 원칙

관리자 화면은 모바일 상담 화면과 달리 1,200px 이상의 desktop 작업 폭을 우선한다. 다만 동일한 색상 토큰·접근성 원칙을 사용한다.

- 차량은 내부 코드가 아니라 `아반떼 2025` 같은 표시명으로만 목록·상세·선택 UI에 표현한다.
- 매뉴얼 업로드는 파일 선택, 검증/인덱싱 상태, 기본 `READY` 매뉴얼 확인, 공개 검토를 단계로 나누며 한 버튼으로 즉시 공개하지 않는다.
- `READY`와 `ACTIVE`는 같은 뜻이 아니다. 전자는 문서 적재 준비 완료, 후자는 사용자의 신규 차량 등록에 공개된 상태다.
- S3 object key, bucket, presigned URL, 장기 자격증명은 관리자 UI에도 표시하지 않는다.
- 화면 기준은 [와이어프레임의 관리자 화면](./와이어프레임.md#09-관리자-차량-카탈로그)과 [관리자 운영 설계](./관리자_카탈로그_및_매뉴얼운영_설계.md)를 따른다.
