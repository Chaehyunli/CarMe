## 현재 확정된 핵심 원칙

- 사용자는 모델·연식만 선택하며, 세부 옵션·트림 구성은 등록하지 않는다.
- 선택 차량에 적용되는 `READY` 매뉴얼만 검색한다. 어떤 매뉴얼을 쓸지는 DB 매핑으로 결정한다.
- LangChain RAG는 선택된 매뉴얼 내부에서 `목차 섹션 → 페이지 청크 → 근거 검증 → 답변` 순으로 동작한다.
- PDF 원본은 private S3/MinIO에 저장한다. 사용자가 현재 세션에서 문서 다운로드를 누를 때만 짧은 만료의 presigned URL을 발급한다.
- 근거 부족·위험 상황에서는 해결책을 추정하지 않는다.
- 채팅은 LangChain in-memory 단기 기억만 사용한다. DB에 대화·답변·citation을 저장하지 않으며, 화면 이탈·30분 유휴·API 재시작 시 종료된다.
- `READY`는 파일 검증, 색인, 매뉴얼 평가 세트 통과까지 끝난 상태다. `ACTIVE`는 기본 `READY` 매뉴얼을 가진 차량 공개 상태다.

## 구현 변경 규칙

1. API request/response 또는 상태값을 바꾸면 API 명세서와 frontend/backend `schedule.md`를 함께 갱신한다.
2. 테이블·필드·관계를 바꾸면 ERD와 Alembic migration을 같은 변경에 포함한다.
3. 새 차종·연식 매뉴얼을 `READY`로 만들 때는 `vehicle_catalog` 한 행, `manual_applicability`, 평가 세트를 함께 추가한다.
