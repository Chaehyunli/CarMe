# CarMe RAG 질문 시나리오 평가 세트

## 목적

사용자는 기능명만 정확히 입력하지 않는다. 조작 방법, 차량에서 겪는 현상, 계기판 문구, 차량 사양, 매뉴얼 범위, 앞선 대화의 대명사를 섞어 질문한다. 이 문서는 그런 실제 입력을 기준으로 검색·답변 변경이 안전한지 확인하는 회귀 평가 세트다.

각 실행에서 상태, 인용 PDF 쪽, 인용문이 기대와 맞는지 기록한다. `GROUNDED`와 `CLARIFYING`은 반드시 하나 이상의 실제 PDF 근거를 가져야 하며, PDF가 바뀌면 gold 쪽도 함께 갱신한다.

| 4 | `주행 중 경고 문구가 떴어` | - | 경고/현상 | `CLARIFYING` 또는 안전 전환 | 표시 문구를 추가로 요청 |
| 5 | `와이퍼 속도는 어디서 바꿔?` | - | 조작 | `GROUNDED` | 조작부·단계 근거 |

## 실행 규칙

- 현재 세션은 DB에 저장하지 않는다. API 프로세스 안의 `history` 최근 4턴만 #22~#26의 대명사 해석과 답변 문맥에 사용한다.
- 모델이 중단되거나 3초 내 응답하지 않으면 규칙 폴백으로 같은 검색을 수행한다. LLM 불가가 사용자의 질문 자체를 거절하는 이유가 되면 안 된다.
- PDF에 정확한 절차가 없고 인접한 사실만 있으면 `CLARIFYING`으로 전환한다. 예: 내비게이션 연동 화면 설명은 시스템 초기화 절차의 근거가 아니다.
- `GROUNDED`의 citation page precision은 100%여야 한다. 질문과 문단의 단어 일부만 겹친 경우는 실패로 기록한다.
