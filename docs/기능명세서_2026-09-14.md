# CarMe 기능명세서 — 차량별 매뉴얼 상담 MVP

| 항목 | 내용 |
|---|---|
| 프로젝트명 | CarMe |
| 버전 | MVP v1 |
| 기준일 | 2026-09-14 |
| 지원 범위 | S3에 적재되어 `READY` 상태인 현대차 모델·연식별 공식 매뉴얼 |
| 초기 검증 데이터 | `CN7_2025_ko_KR.pdf`; 서비스 지원 범위를 CN7로 제한하지 않음 |
| 지원 기기 | 모바일 웹 우선, 데스크톱 웹 |
| 사용자 역할 | 고객(`USER`), 운영자(`ADMIN`) |

## 1. 제품 정책과 범위

### 1.1 한 줄 정의

등록 차량의 공식 취급설명서에서 근거를 찾아 원문 쪽수와 함께 안내하는 셀프서비스 탐색 보조 서비스다.

### 1.2 포함·제외 범위

| 포함 | 제외 |
|---|---|
| 카카오 로그인, 차량 등록, 자연어·카테고리 질문, 매뉴얼 RAG, 근거 카드, PDF 원문 보기, 단기 채팅, 상담 전환 안내, 관리자 카탈로그·매뉴얼 운영 | 정비 진단·원인 확정, 실제 차량 데이터 연동, 가격·구매 가능 여부, 실제 옵션 장착 판정, 리콜 정보, 실제 예약 처리·상담원 화면, 상담 이력 |

고객은 차량의 세부 옵션·트림 구성을 등록하지 않는다. 서비스는 사용자가 선택한 **모델·연식**에 매핑된 통합 매뉴얼 전체를 검색해 답한다. 즉, 옵션 장착 여부는 확인·판정하지 않고, 통합 매뉴얼에 포함된 기능을 안내한다. 차량 등록 및 상담 화면에는 “세부 옵션 구성은 확인하지 않으며, 선택 차량의 통합 매뉴얼을 기준으로 안내합니다”를 표시한다.

### 1.3 공통 상태값

| 상태 | 사용자 화면 | 생성 규칙 |
|---|---|---|
| `GROUNDED` | 답변·근거 카드·원문 보기·해결 여부 | 매뉴얼 청크가 답변의 모든 조치·주의 내용을 뒷받침할 때 |
| `AMBIGUOUS` | 짧은 추가 질문 | 증상, 발생 조건 또는 장치 정보가 부족할 때 |
| `INSUFFICIENT_EVIDENCE` | “매뉴얼에서 확인하지 못했어요”와 상담 전환 | 검색 결과가 임계값 미만이거나 주장 검증 실패 시 |
| `SAFETY_ESCALATION` | 즉시 안전 안내·공식 지원 경로 | 위험 사전 규칙에 해당할 때 |

`INSUFFICIENT_EVIDENCE`와 `SAFETY_ESCALATION`에는 AI가 추정한 해결책을 표시하지 않는다.

## 2. 기능 명세

## 2.1 카카오 로그인과 세션 관리

> 중요도: 높음

고객은 카카오 OAuth로만 로그인한다. 자체 비밀번호 회원가입은 제공하지 않는다. 내부 계정은 카카오 고유 식별자(`kakao_subject`)로 생성·연결되고, 서비스 API에는 access JWT와 refresh token을 사용한다.

**수용 기준**

1. 로그인하지 않은 사용자는 차량과 채팅 세션 URL에 접근할 수 없다.
2. 카카오 콜백의 동일한 `kakao_subject`는 기존 내부 사용자로 연결된다.
3. 인증 취소·필수 동의 거부·토큰 오류에는 보호 정보를 표시하지 않고 로그인 화면으로 돌아간다.
4. 로그아웃·토큰 만료 후 refresh token을 재사용할 수 없다.

**데이터·정책**

- `user`: 내부 ID, 카카오 식별자, 생성·최근 로그인 시각만 저장한다.
- 전화번호, 카카오 비밀번호, 불필요한 프로필 정보는 저장하지 않는다.
- JWT 만료 시간, refresh token 보관 방식(HttpOnly/Secure cookie 권장), CORS 허용 origin을 배포 전 확정한다.

## 2.2 내 차량 등록·관리

> 중요도: 높음

고객은 지원 목록에서 차량 모델과 연식을 선택하고 별칭을 붙일 수 있다. 세부 옵션·트림·모델 구분은 등록받지 않는다. 등록 가능한 목록은 기본 `READY` 매뉴얼이 있고 `manual_applicability`가 설정된 모델·연식만 노출한다.

**수용 기준**

1. 지원 목록에는 매뉴얼이 적재·검수 완료된 모델·연식만 나타난다.
2. 등록된 차량은 `vehicle_catalog`와 연결되고, 적용 가능한 `READY` 매뉴얼을 조회할 수 있다.
3. 사용자는 본인 차량만 조회·별칭 수정·삭제할 수 있다.
4. 동일 차량을 여러 번 등록할 수 있는지 정책을 구현 전에 결정한다. 권장안은 사용자당 같은 차량 선택 조합 1대이며 별칭 수정만 허용하는 것이다.
5. 차량 삭제 시 연결된 살아 있는 단기 채팅 세션을 즉시 종료한다.

## 2.3 질문 입력과 분류

> 중요도: 높음

고객은 차량을 선택한 뒤 증상 카테고리, 세부 증상 버튼 또는 자유 텍스트로 질문한다. 카테고리는 검색어를 대신하는 정답 데이터가 아니라, 고령 사용자 입력을 돕기 위한 질문 초안이다.

초기 카테고리는 `시동·주행`, `경고등·클러스터`, `공조·편의`, `문·창문·키`, `타이어·정기점검`, `비상시 응급조치`, `기타`로 시작한다. 버튼 선택 시에도 고객이 문장을 수정·추가할 수 있어야 한다.

**수용 기준**

1. 질문은 선택 차량이 있는 상담 세션에만 전송된다.
2. 사용자 메시지는 DB에 저장하지 않고 현재 단기 세션의 메모리에만 둔다.
3. 위험 사전 규칙은 RAG·LLM 호출 전에 적용된다.
4. 모호한 질문은 매뉴얼 근거가 충분하지 않을 때 추가 질문 상태로 끝난다.

## 2.4 선택 차량 한정 매뉴얼 검색·답변

> 중요도: 높음

서비스는 선택 차량의 `vehicle_catalog`에 `manual_applicability`로 연결된 `READY` 매뉴얼 청크만 검색한다. 한 차량에 사용설명서·내비게이션 설명서처럼 여러 문서가 연결되면 모두 검색하되, 다른 모델·연식 문서는 절대 검색하지 않는다. 최근 같은 세션의 4개 메시지, 최대 2,000 토큰만 문맥으로 사용하며 세션 밖의 이력은 존재하지 않는다.

**처리 순서**

1. 사용자가 선택한 차량 항목의 접근 권한과 매뉴얼 적용 가능 여부를 확인한다. 실제 차량 소유권은 확인하지 않는다.
2. 위험·범위 밖·모호 여부를 분류한다.
3. DB가 선택 차량에 적용되는 `READY` 매뉴얼 ID를 결정한다.
4. LangChain 체인이 해당 매뉴얼의 목차 섹션을 1차 검색하고, 선택 섹션의 페이지 청크를 2차 검색·재정렬한다.
5. 임계값과 근거 검증을 통과한 경우에만 최종 청크를 LLM에 전달해 답변을 생성한다.
6. 답변의 모든 행동 지시와 주의 문장을 인용 청크에 대조한다.
7. 결과 상태, 답변 또는 전환 안내, 인용을 이번 API 응답으로만 반환하고 단기 메모리에 최근 문맥만 남긴다.

**수용 기준**

1. 선택 차량에 매핑되지 않은 차종·연식·문서와 인덱싱 실패 문서는 검색 대상이 아니다.
2. 근거 있는 답변은 하나 이상의 인용을 가진다.
3. 인용문은 LLM이 만든 문장이 아니라 저장된 매뉴얼 원문 문자열이다.
4. 매뉴얼의 경고·주의·금지 의미는 요약에서 누락하지 않는다.
5. 옵션·트림 관련 설명은 선택 차량의 통합 매뉴얼에 포함된 기능 안내로 처리하며, 서비스가 장착 여부를 판정하지 않는다는 화면 고지를 유지한다.
6. 매 요청에서 PDF 원본 전체를 다시 읽거나 LLM에 전달하지 않는다. 적재된 목차·섹션·페이지 청크만 사용한다.

## 2.5 근거 카드와 원문 보기

> 중요도: 높음

근거 카드에는 매뉴얼 제목, 원문 스니펫, PDF 페이지, 인쇄 쪽수(알 수 있는 경우)를 표시한다. 고객이 원문 보기를 선택하면 backend가 private object storage의 PDF에 대한 짧은 만료 presigned URL을 발급한다.

**수용 기준**

1. 근거 카드는 이번 응답의 검증된 `manual_chunk`에서 서버가 생성한다.
2. PDF 링크에는 인용한 PDF 페이지 번호가 유지된다.
3. 브라우저가 `#page` 이동을 지원하지 않아도 페이지 번호는 화면에서 확인할 수 있다.
4. 원본 PDF bucket은 공개 읽기 권한을 갖지 않는다.

## 2.6 안전 전환과 상담원 연결 안내

> 중요도: 높음

제동·조향 이상, 화재/연기/연료 누출 의심, 주행 중 심한 이상, 사고 등 위험 가능성이 있는 표현은 `SAFETY_ESCALATION`으로 처리한다. 매뉴얼 근거를 찾지 못한 일반 질문은 `INSUFFICIENT_EVIDENCE`로 처리한다.

**수용 기준**

1. 두 상태 모두 근거 없는 해결 방법을 생성하지 않는다.
2. 안전 전환은 일반 상담 전환과 다른 우선 경고 문구를 사용한다.
3. 전화 또는 외부 예약 링크의 실제 값, 운영 시간, 책임 문구를 배포 전에 확정한다.
4. 예약 시스템이 없다면 예약 버튼은 표시하지 않는다. MVP는 안내·외부 링크까지만 제공한다.
5. `SAFETY_ESCALATION`에는 PDF citation·원문 보기 카드를 붙이지 않는다.

## 2.7 단기 채팅 세션

> 중요도: 중간

고객은 차량 선택만으로 빈 채팅 세션을 시작한다. LangChain `InMemoryChatMessageHistory`에는 같은 세션의 최근 4개 메시지, 최대 2,000 토큰만 둔다. 대화·답변·citation은 DB나 브라우저 저장소에 저장하지 않는다.

**수용 기준**

1. 화면 이탈 시 `DELETE /chat-sessions/{id}`로 즉시 메모리를 삭제한다.
2. 30분 idle TTL, API 재시작·배포, 다중 worker/replica는 세션 종료 사유다. MVP는 단일 API process/worker로 운영한다.
3. 만료된 세션 메시지 요청은 `410 CHAT_SESSION_EXPIRED`이고, 사용자는 새 세션을 시작한다.
4. 과거 상담 목록·세션 재개·citation 재조회 기능은 제공하지 않는다.

## 2.8 문서 적재와 운영자 작업

> 중요도: 높음, 고객 화면 없음

운영자는 원본 PDF를 private S3 bucket에 저장한 후 적재 명령을 실행한다. 적재는 해시 중복 검사, 페이지 추출, 청킹, 임베딩, 표본 검수, `READY` 전환 순서로 수행한다.

**수용 기준**

1. 같은 SHA-256 파일은 중복 인덱싱하지 않는다.
2. 실패한 문서는 `FAILED` 상태와 오류 원인을 남기며 검색에서 제외된다.
3. 매뉴얼이 `READY`가 아니면 차량 등록 또는 상담에서 지원 불가 상태를 명확히 보여 준다.
4. 초기에는 추출기·청커·임베딩 모델 버전과 실행 시각을 `manual` 메타데이터·구조화 로그·적재 manifest에 남긴다.

## 3. 접근 제어·보존 정책

### 3.1 인가

- 모든 보호 요청은 JWT를 검증한다.
- 사용자별 선택 차량 항목의 접근 권한을 인가 기준으로 삼는다. 채팅 세션은 메모리에 든 `user_id`, `vehicle_id`가 요청 사용자와 일치할 때만 접근한다. 실제 차량 소유권·VIN은 수집하거나 검증하지 않는다.
- 응답에서 내부 object key, S3 자격증명, 다른 사용자의 ID를 노출하지 않는다.

### 3.2 보존과 삭제

- 원본 매뉴얼은 데모 목적·이용 권한이 유효한 기간에만 private storage에 보관한다.
- 사용자는 차량 삭제와 별개로 계정 삭제를 요청할 수 있어야 한다. 채팅 이력은 저장하지 않으므로 별도 삭제 대상이 없다.
- 권장 MVP 기본값: 계정은 삭제 요청 후 30일 내 삭제, 운영 로그는 개인정보를 제거해 90일 보관, 매뉴얼 원본은 소스 이용 정책 종료 시 삭제한다.
- PDF와 카탈로그는 현대자동차 저작물임을 서비스 화면과 README에 고지한다.

## 4. 품질 지표와 출시 게이트

적재한 각 모델·연식 매뉴얼마다 평가 세트를 작성한다. CN7 2025 파일은 첫 검증 세트일 뿐이며, 새 매뉴얼도 `READY` 전환 전에 같은 게이트를 통과해야 한다. 세트는 근거 질문 30개, 범위 밖 질문 10개, 위험 질문 10개, 통합 매뉴얼 기능 질문 10개로 구성하며 각 질문에는 기대 상태·정답 페이지·필수 주의 문구를 기록한다.

| 지표 | MVP 게이트 |
|---|---|
| 근거 질문의 정답+정확 페이지 인용 | 90% 이상 |
| 범위 밖 질문의 추정 답변 미생성 | 95% 이상 |
| 위험 질문의 안전 전환 누락 | 0건 |
| 인용 스니펫 원문 일치 | 100% |
| 대표 질문 P95 응답 시간 | 8초 이하 |
| 타 사용자 리소스 접근 허용 | 0건 |
