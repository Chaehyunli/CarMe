## 1. 프로젝트 개요
---
### 한 줄 정의
현대차 매뉴얼 RAG 상담

### 제품 목표
현대차 고객이 등록한 차량의 공식 매뉴얼을 바탕으로 증상 해결 방법을 빠르게 찾고, 문서명·페이지·인용문으로 답변을 검증할 수 있는 무료 셀프서비스 상담을 제공한다.

### 배경
고객 문의는 차량 증상 중심으로 발생하지만, 특히 고령 고객은 홈페이지에서 긴 매뉴얼의 관련 내용을 직접 찾기 어렵다. 초기에는 2~3개 차종의 매뉴얼 기반 RAG와 차량 등록·상담 이력에 집중하며, 향후 차량 상태 연동을 통한 AI 점검·해결 서비스로 확장할 수 있다.

### 사용자 문제
고객은 자신의 차량에서 발생한 증상을 설명해도 원인과 조치 방법을 즉시 알기 어렵고, 해당 차종·연식의 매뉴얼에서 정확한 정보를 찾아 검증하기도 어렵다. 근거 없는 AI 답변은 안전 및 신뢰 측면에서 위험하며, 해결되지 않은 문제를 적절한 상담 채널로 전환할 수 있어야 한다.

### 해결 방안
고객이 차종·연식·트림을 등록하면 연결된 매뉴얼만 검색하여 증상 카테고리 또는 자연어 질문에 답한다. 답변에는 해결 요약과 문서명·페이지·스니펫을 표시하고, 원문 PDF의 해당 페이지를 열 수 있게 한다. 근거가 부족하거나 해결되지 않으면 답변을 추정하지 않고 상담원 연결을 안내한다. 가격·옵션의 정확한 조회는 RAG 대신 구조화된 옵션 데이터로 처리한다.

### 차별점
등록 차량에 매핑된 공식 매뉴얼로 검색 범위를 제한하고 모든 답변에 페이지 단위 근거를 제공한다. 근거가 없을 때 답변 생성을 중단하고 상담원 연결로 폴백하여 환각을 줄인다. 증상형·설명형 질문은 RAG, 가격·옵션의 사실 조회는 구조화 데이터로 분리한다.

### 타겟 사용자
현대차를 보유한 고객 중 차량 기능 이상 또는 사용 방법을 스스로 확인하려는 사용자이며, 특히 긴 온라인 매뉴얼 탐색이 어려운 고령 고객을 우선 고려한다. 초기 서비스는 선정된 2~3개 차종을 보유하고 차종·연식·트림을 선택해 등록할 수 있는 모바일 및 웹 사용자에게 제공한다.

### 사용자 시나리오
고객은 가입·로그인 후 자신의 차종, 연식, 트림을 드롭다운에서 선택해 등록한다. 홈에서 증상 카테고리를 고르거나 자연어로 질문하면 서비스는 해당 차량 매뉴얼 근거와 함께 조치 방법을 제시한다. 고객은 근거 카드에서 원문 페이지를 확인하고, 해결되지 않았거나 근거가 없으면 전화 또는 예약 방식의 상담원 연결을 선택한다. 고객은 차량별 이전 상담 기록을 조회한다.

### 핵심 지표
초기 데모에서 선정 차종의 대표 증상 질의가 정확한 매뉴얼 페이지 인용과 함께 응답되는 비율을 측정한다. 근거가 없는 질의는 추정 답변 없이 상담원 연결 안내로 전환되는 비율을 측정한다. 차량 등록 완료율, 상담 질의 완료율, 근거 카드·원문 보기 이용률을 관찰한다.

### 리스크
대상 차종의 공식 PDF URL과 모델코드 매핑, 카탈로그의 동적 다운로드 구조를 사전 검증해야 한다. 매뉴얼·카탈로그 저작권과 비상업적 데모 목적을 명시하고, 수집 시 요청 지연 및 캐싱을 적용해야 한다. RAG 검색 오류나 근거 부족 답변은 차량 안전 문제로 이어질 수 있으므로 근거 기반 제약과 상담원 폴백을 강제해야 한다. 초기 3일 일정에서는 카탈로그 수집과 선택 부가기능을 핵심 범위에서 제외한다.

## 1. 계정 및 차량 등록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

고객은 로그인 후 자신의 차량을 차종·연식·트림 선택으로 등록하고 등록된 차량 목록과 상세 정보를 조회한다. 차량 등록 시 해당 조합에 연결되는 매뉴얼을 미리 계산해 저장한다. 자유 텍스트 차량 입력과 타인 차량 조회는 포함하지 않는다.

**수용 기준:**
```
1. ○ 고객은 차종, 연식, 트림을 선택하여 차량을 등록할 수 있다.
2. ○ 등록된 차량에는 매칭된 매뉴얼 연결 정보가 저장된다.
3. ○ 고객은 본인 소유 차량만 조회할 수 있다.
```


### 1.1 회원가입 및 로그인
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 고객 | **기기**: 모바일 웹, 데스크톱 웹

**기능의 근거**: 카카오 계정 기반 인증으로 계정 소유를 확인해 차량과 상담 기록을 고객별로 안전하게 분리해야 한다.

고객은 카카오 소셜 로그인을 통해 본인 카카오 계정으로 가입하고 로그인하여 자신의 차량과 상담 정보에 접근한다. 로그인 성공 시 서비스는 카카오 계정의 고유 식별자에 연결된 내부 고객 계정과 보호 API용 인증 정보를 발급한다. 자체 비밀번호 로그인, 관리자 역할, 역할별 권한 계층은 초기 범위에 포함하지 않는다.

**성공 기준**: 카카오 로그인 완료율과 인증 실패율을 측정한다.

**개발 준비 슬롯**
- **선행조건**: - 고객은 카카오 계정으로 로그인할 수 있어야 한다.
  - 서비스에는 카카오 로그인 앱 키와 승인된 리디렉션 주소가 설정되어 있어야 한다.
- **트리거**: - 고객이 로그인 화면의 카카오 로그인 버튼을 선택하면 카카오 인증을 시작한다.
- **동작**: - 서비스는 고객을 카카오 인증 화면으로 이동시킨다.
  - 서비스는 카카오 인증 결과의 고유 사용자 식별자를 확인하고 내부 고객 계정을 생성하거나 기존 계정에 연결한다.
  - 서비스는 인증이 완료된 고객에게 보호된 서비스 요청에 사용할 JWT를 발급한다.
- **결과**: - 카카오 인증이 성공한 고객은 내부 고객 계정에 로그인된 상태가 된다.
  - 로그인에 성공한 고객에게는 보호된 서비스 요청에 사용할 JWT가 발급된다.
  - 서비스는 카카오 로그인 완료 이벤트를 기록한다.
- **예외**: - 카카오 인증이 취소되거나 실패하면 보호된 서비스 접근을 허용하지 않는다.
  - 필수 동의 항목 제공을 거부한 고객의 로그인을 중단하고 재동의를 안내한다.
- **표시**: - 로그인 화면은 카카오 로그인 버튼을 제공한다.
  - 인증 실패 또는 취소 시 화면은 다시 로그인할 수 있는 안내를 표시한다.
- **권한 & 접근**: - 로그인하지 않은 고객은 차량, 상담 이력, 상담 기능에 접근할 수 없다.
  - 카카오 인증을 완료한 고객은 본인 계정의 보호된 기능에 접근할 수 있다.
- **비즈니스 규칙**: - 내부 고객 계정은 카카오 계정의 고유 사용자 식별자를 기준으로 식별한다.
  - 서비스는 카카오 계정에서 제공받은 비밀번호를 저장하지 않는다.
- **데이터**: - 고객 계정은 내부 고객 식별자, 카카오 고유 사용자 식별자, 생성 시각, 최근 로그인 시각을 저장한다.
  - 카카오 고유 사용자 식별자는 고객 계정마다 하나만 연결되도록 관리한다.


### 1.2 내 차량 선택 등록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 고객 | **기기**: 모바일 웹, 데스크톱 웹

**기능의 근거**: 차량별 매뉴얼 검색 범위를 정확히 제한하려면 고객 차량 정보가 필요하다.

고객은 제공된 차종, 연식, 트림 목록에서 자신의 차량 정보를 선택해 등록한다. 등록 완료 시 서비스는 차량에 적용되는 매뉴얼 연결 정보를 준비한다. 자유 입력 차량 등록과 지원하지 않는 차종 등록은 포함하지 않는다.

**성공 기준**: 차량 등록 완료율을 측정한다.

**개발 준비 슬롯**
- **선행조건**: - 고객은 로그인한 상태여야 한다.
- **동작**: - 고객은 차종, 연식, 트림을 순서대로 선택하여 차량 등록을 요청한다.
- **결과**: - 등록 차량에는 매칭된 매뉴얼 연결 정보가 저장된다.
- **표시**: - 화면은 텍스트 입력 대신 차종, 연식, 트림 선택 목록을 제공한다.

## 2. 매뉴얼 기반 증상 및 옵션 상담
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

고객은 등록 차량을 선택해 증상 카테고리 또는 자연어로 질문하고, 차량 구매 시 선택한 유료 옵션의 기능과 사용 방법도 질문할 수 있다. 서비스는 선택 차량에 연결된 공식 매뉴얼만 검색하여 답하고 세션 내 최근 대화만 문맥으로 사용한다. 장기 개인화 메모리와 차량 상태 실시간 진단, 옵션 가격 및 구매 가능 여부 조회는 초기 범위에서 제외한다.

**수용 기준:**
```
1. ○ 증상 및 구매 옵션 관련 질의 검색은 선택 차량에 연결된 매뉴얼 범위로 제한된다.
2. ○ 고객은 증상 카테고리, 자유 텍스트, 구매 옵션의 기능 및 사용 방법 질문으로 상담할 수 있다.
3. ○ 상담 답변은 세션 내 최근 메시지만 문맥으로 활용한다.
```


### 2.1 증상 질문 입력
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 고객 | **기기**: 모바일 웹, 데스크톱 웹

**기능의 근거**: 고객이 매뉴얼 용어를 몰라도 증상 중심으로 문제를 설명할 수 있어야 한다.

고객은 선택한 등록 차량에 대해 증상 카테고리·세부 증상을 고르거나 자연어로 질문을 입력한다. 질문은 새 상담 세션 또는 진행 중인 상담 세션에 기록된다. 차량 상태의 자동 수집과 장기 메모리 기반 질문 추천은 포함하지 않는다.

**성공 기준**: 상담 질의 완료율을 측정한다.

**개발 준비 슬롯**
- **선행조건**: - 고객은 본인 소유의 등록 차량을 선택해야 한다.
- **동작**: - 고객은 증상 카테고리와 세부 증상을 선택하거나 자유 텍스트로 질문을 입력한다.
- **데이터**: - 상담 세션은 고객 식별자와 선택 차량 식별자를 연결해 저장한다.
  - 메시지는 상담 세션, 발화 역할, 내용으로 저장한다.


### 2.2 차량 한정 매뉴얼 검색 답변
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 고객 | **기기**: 모바일 웹, 데스크톱 웹

**기능의 근거**: 잘못된 차종의 안내를 방지하고 공식 문서 기반의 신뢰 가능한 상담을 제공하기 위해 필요하다.

서비스는 고객 질문에 대해 선택 차량과 연결된 공식 매뉴얼 청크만 검색하고 그 범위에서 해결 답변을 생성한다. 증상뿐 아니라 차량 구매 시 선택한 유료 옵션의 기능과 사용 방법 질문도 같은 매뉴얼 검색 범위에서 처리한다. 세션 내 최근 메시지는 문맥으로 활용하며, 연결되지 않은 차량 문서 검색과 장기 대화 이력의 모델 재입력은 제외한다.

**성공 기준**: 대표 증상 및 옵션 질의의 근거 포함 응답 비율을 측정한다.

**개발 준비 슬롯**
- **선행조건**: - 선택 차량에는 검색 대상 매뉴얼이 연결되어 있어야 한다.
- **동작**: - 서비스는 선택 차량에 연결된 매뉴얼의 청크를 대상으로 질문과 유사한 내용을 검색한다.

공식 매뉴얼과 카탈로그를 비상업적 데모·포트폴리오 범위에서 취급하기 위한 데이터 이용 원칙이다.

### 2. 상담 답변 신뢰성

적용 범위: - 증상형, 기능 설명형, 차량 구매 옵션의 기능 및 사용 방법 질의는 등록 차량에 연결된 공식 매뉴얼 검색 결과에만 근거해 답변한다.
- 옵션 가격과 구매 가능 여부는 초기 상담 답변 범위에서 제외한다.

근거 제약: - 상담 답변은 검색된 매뉴얼 청크의 내용 범위 안에서만 생성한다.
- 근거가 있는 상담 답변에는 문서명, 페이지 번호, 인용 스니펫을 함께 제공한다.
- 등록 차량과 연결되지 않은 매뉴얼은 상담 검색 대상에서 제외한다.

근거 부족 및 해결 실패: - 검색 근거가 부족한 질의에는 해결 방법을 추정해 제시하지 않고 알 수 없음을 안내한다.
- 고객이 해결되지 않았다고 표시한 상담에는 상담원 연결 수단을 안내한다.

차량 증상 및 구매 옵션 상담에서 근거 기반 응답과 상담 전환을 일관되게 적용하기 위한 정책이다.

### 3. 접근 권한 정책

보호 대상: - 차량, 대화, 메시지, 인용 정보는 고객 소유의 보호 리소스로 취급한다.

인증 및 소유권 검증: - 보호된 서비스 요청은 JWT 인증 정보를 요구한다.
- 차량과 대화 리소스는 요청자의 사용자 식별자와 리소스 소유자 식별자가 일치하는 경우에만 조회하거나 변경할 수 있다.
- 소유자가 아닌 고객의 리소스 접근 요청은 거부한다.

고객 소유 데이터의 인증과 접근 범위를 정한다.
