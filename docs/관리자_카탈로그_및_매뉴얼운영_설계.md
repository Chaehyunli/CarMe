# 관리자 카탈로그·매뉴얼 운영 설계 — 초기 MVP

관리자 기능은 **차량 한 행 생성 → 매뉴얼 연결·업로드 → 적재 완료 후 공개**만 제공한다. 상세 실행 이력, 승인 단계, 감사 로그는 초기 MVP 밖이다.

## 1. 관리자 화면의 관리 단위

관리자도 내부 코드가 아닌 사람이 읽는 정보만 본다.

| 입력/표시 | 예시 | DB |
|---|---|---|
| 제조사 | 현대 | `manufacturer` |
| 차종 | 아반떼 | `model_name` |
| 연식 | 2025 | `model_year` |
| 표시명 | 아반떼 2025 | 서버 생성 `display_name` |

`아반떼 2025`와 `아반떼 2026`은 `vehicle_catalog`의 서로 다른 행이다. `CN7` 같은 내부 코드, S3 object key, bucket, presigned URL, 장기 자격증명은 화면에 표시하지 않는다.

## 2. 권한

- `USER`: 자기 차량·상담만 접근한다. `/admin/*`은 `403`이다.
- `ADMIN`: 차량 카탈로그와 매뉴얼을 생성·수정·공개·보관한다.
- 역할은 DB 초기 데이터/운영 절차로만 부여한다. 회원가입·내 정보 API에서 역할 변경은 불가하다.
- 초기에는 `admin_audit_log` 테이블을 만들지 않는다. 변경 요청은 request ID, 관리자 ID, action, 대상 ID, 결과 상태를 구조화 애플리케이션 로그에 남긴다.

## 3. 최소 상태 전이

```text
차량 카탈로그: DRAFT → ACTIVE → ARCHIVED
매뉴얼:         DRAFT → UPLOADED → INDEXING → READY → ARCHIVED
                                  └──────→ FAILED → UPLOADED
```

- `ACTIVE` 전환 조건: 해당 차량에 `is_primary = true`인 `READY` 매뉴얼이 하나 있어야 한다.
- `ACTIVE` 차량만 사용자 차량 선택 목록에 표시한다.
- `ARCHIVED` 차량/매뉴얼은 신규 등록과 새 상담에서 제외한다.
- 초기 MVP는 별도 품질 게이트 DB 테이블을 만들지 않는다. 첫 매뉴얼은 적재 후 정해 둔 평가 질문을 수동/스크립트로 확인하고 관리자가 `ACTIVE`로 바꾼다.

## 4. 업로드와 적재 흐름

```text
관리자: 차량 카탈로그 초안 생성
  → 매뉴얼 초안 생성 및 차량 연결
  → upload-url 요청 (PDF 파일명, 크기, SHA-256)
  → private S3에 직접 PUT
  → upload-complete 호출
  → 서버가 파일·해시·페이지 수 검증
  → worker가 목차·청크·임베딩 생성
  → manual.status = READY
  → 관리자: 차량 카탈로그 ACTIVE 공개
```

- 업로드 URL은 PDF 하나에만 쓸 수 있고 짧게 만료된다.
- `upload-complete` 신호만으로 상태를 바꾸지 않는다. 서버가 storage의 파일 타입·크기·해시·PDF 페이지 수를 재검증한다.
- PDF 추출과 임베딩은 API 요청에서 실행하지 않고 worker/CLI에서 실행한다.
- 초기에는 `manual.status`, `ingestion_error`, worker 로그로 적재 상태를 본다. 실행 이력 테이블은 나중에 추가한다.
- 개정 PDF는 기존 `READY` 매뉴얼을 덮어쓰지 않고 새 `manual`로 등록한다.

## 5. RAG와의 연결

새 상담 또는 질문 시 backend는 `vehicle.catalog_id`에서 `manual_applicability`를 조회해 현재 `READY` 매뉴얼만 결정한다. 이후 RAG는 해당 문서의 `manual_section → manual_chunk`만 검색한다.

초기에는 `conversation_manual` 스냅샷이 없으므로, 관리자가 연결 매뉴얼을 바꾸면 기존 상담에서 다음 질문을 할 때 새 매뉴얼이 검색될 수 있다. 과거 상담의 검색 범위를 완전히 재현해야 하는 요구가 생기면 그때 `conversation_manual`을 추가한다. 이미 저장된 답변의 citation은 `manual_id`와 PDF 페이지를 직접 저장하므로 답변 근거 표시는 유지된다.

## 6. 화면/API 범위

| 화면 | API | 핵심 행동 |
|---|---|---|
| 차량 카탈로그 | `GET/POST /admin/vehicle-catalog` | `아반떼`, `2025` 입력으로 초안 생성 |
| 차량 상세 | `GET/PATCH /admin/vehicle-catalog/{id}` | 연결된 매뉴얼 확인, `ACTIVE`/`ARCHIVED` 전환 |
| 매뉴얼 업로드 | `POST /admin/manuals`, upload URL, upload complete | PDF 직접 업로드와 적재 상태 확인 |

## 7. 초기 MVP 수용 기준

- [ ] 관리자 화면이 `아반떼 2025` 같은 표시명만 보여 준다.
- [ ] 일반 사용자는 모든 관리자 API에서 `403`을 받는다.
- [ ] `READY` 기본 매뉴얼이 없으면 차량 공개가 `409 CATALOG_NOT_PUBLISHABLE`이다.
- [ ] upload URL은 파일 하나·짧은 만료·PDF MIME으로 제한된다.
- [ ] `manual_chunk`에 실제 PDF 페이지 번호가 저장되고 답변 citation에 그대로 반환된다.
- [ ] 매뉴얼 교체 후 과거 답변 citation은 계속 문서명·페이지 번호를 표시한다.
