# 로컬 RAG 품질 평가

일반 단위 테스트와 분리된, 실제 로컬 데이터베이스 평가 묶음입니다. 관리자 화면에서 준비 완료된 PDF 청크와 차량별로 저장된 현대 공식 웹 안내를 동시에 검색합니다. 질문마다 선택된 근거의 종류, 제목 또는 PDF 쪽수, 점수, 근거 판정 사유를 출력합니다.

## 실행

`backend` 폴더에서 실행합니다.

```bash
CARME_RUN_RAG_EVAL=1 pytest tests/rag_eval -q -s
```

전체 일반 테스트와 섞지 않고 이 폴더만 실행하므로, 실제 임베딩 검색을 수행하는 시간이 일반 테스트에 영향을 주지 않습니다. 환경 변수가 없으면 이 평가 묶음은 건너뜁니다.

## 평가 시나리오

`test_local_corpus_quality.py`는 아반떼 2025와 쏘나타 택시 2025 각각에 대해 다음을 확인합니다.

1. 블루투스 신규 기기 연결, 등록 기기 연결, 블루투스 음악 재생은 PDF의 일반 안전 문구가 아닌 공식 웹 절차를 선택하는지
2. 내비게이션 지도 글자 크기 변경은 차량별 공식 웹 안내를 선택하는지
3. 오토 디포그, 와이퍼, 와셔액, 전자식 파킹 브레이크, 타이어 공기압, 옵션은 해당 차량 PDF의 직접 안내를 선택하는지
4. 에어컨 냉기 부족 같은 현상 질문은 고장 원인을 단정하지 않고 추가 확인 상태가 되는지
5. 이전 질문을 포함한 후속 질문도 올바른 절차를 선택하는지
6. 하늘을 나는 기능 또는 엔진오일과 에어컨의 인과처럼 근거가 없는 질문은 인용 없이 거절하는지

`test_agent_guardrail_flow.py`는 검색 결과 이전과 이후의 Agent 안전 장치를 확인합니다.

1. 브레이크, 연기, 화재, 에어백 같은 위험 신호는 검색과 답변 생성을 건너뛰고 안전 안내로 전환하는지
2. 근거 없는 질문에는 “매뉴얼에서 확인되지 않으며 추측하지 않는다”는 사용자용 문구가 나오는지
3. Answer Agent에 전달되는 내용은 Evidence Gate가 통과시킨 근거 하나뿐인지
4. 모델이 근거 없는 고장 원인 또는 교체 단정을 하면 후처리 가드레일이 차단하는지

실패하면 출력된 한 줄에서 잘못 선택한 출처와 제목 또는 쪽수, 점수, 판정 사유를 확인할 수 있습니다. 그 결과를 기준으로 청크 품질, 공식 안내 동기화, 검색어 확장, 임계값을 조정합니다.

## 선택 사항: 실제 답변 문장 확인

로컬 채팅 모델을 설치한 뒤에는 아래 명령으로 답변 형식도 확인할 수 있습니다. 이 단계는 모델 출력이 달라질 수 있어 기본 평가와 분리했습니다.

```bash
CARME_RUN_RAG_EVAL=1 CARME_RUN_RAG_LLM_EVAL=1 pytest tests/rag_eval -q -s
```

방법 질문은 번호가 있는 안내로 답하는지, PDF 쪽수나 원문 인용을 그대로 노출하지 않는지, 근거 없는 고장 단정을 하지 않는지를 검사합니다.
